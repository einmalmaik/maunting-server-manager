# Hotfix v5.0.1 — Passwort-Manager öffnet auf neuen Geräten wieder

### Übersicht
Version 5.0.1 behebt einen Fehler im Passwort-Manager: Auf einem neuen Gerät oder nach einer Neuinstallation der App meldete der Tresor bei jeder Eingabe „Falsches Master-Passwort“ – auch beim richtigen. Die gespeicherten Einträge waren nie verloren, sie lagen die ganze Zeit verschlüsselt auf dem Server. Mit 5.0.1 kommst du mit deinem richtigen Master-Passwort wieder an sie heran.

---

### Was ist behoben?

#### Passwort-Manager: richtiges Passwort wurde als falsch abgelehnt
* **Wen es traf**: Tresore, die zwischen dem 06.09. und dem 22.09.2026 zum ersten Mal synchronisiert haben, und dann ein neues Gerät, eine Neuinstallation oder ein geleerter App-Speicher. Auf Geräten, auf denen der Tresor schon einmal offen war, lief alles weiter.
* **Was passiert ist**: Mit dem blinden Abgleich (06.09.) hängt ein Tresor nicht mehr am Konto, sondern nur noch an einem Nachweis, den dein Gerät aus dem Master-Passwort berechnet. Dabei hat der Server die Tresor-Kennung von deinem Konto gelöscht. Ein neues Gerät bekam danach vom Server nur noch das Salz, keine Kennung, und hatte auch keinen eigenen Prüfblock. Ohne etwas zum Vergleichen meldete der Tresor pauschal „falsch“.
* **Was jetzt passiert**:
  - Fehlt auf dem Gerät der Prüfblock und nennt der Server keine Kennung, fragt der Tresor den Server, ob der Nachweis zu einem Tresor passt. Das Master-Passwort verlässt dabei nie dein Gerät.
  - **Richtiges Passwort**: Der Tresor öffnet und lädt alle Einträge. Danach liegt der Prüfblock wieder auf dem Gerät, und zum Entsperren braucht es den Server nicht mehr.
  - **Falsches Passwort**: Die Meldung bleibt „Falsches Master-Passwort“, und auf dem Server wird nichts angelegt.
  - **Panel nicht erreichbar**: Du bekommst die Meldung, dass das Passwort nicht am Server geprüft werden konnte, statt fälschlich „falsches Passwort“.

---

### Was du tun musst
* Server und App auf 5.0.1 aktualisieren. Das Server-Update allein reicht nicht: die Prüfung stößt die App an.
* Danach den Tresor mit dem bisherigen Master-Passwort entsperren. Ein neues Einrichten ist nicht nötig. Richte den Tresor auf dem betroffenen Gerät **nicht** neu ein, sonst entsteht ein zweiter, leerer Tresor neben deinem alten.

---

### Technisch
* Neuer Endpunkt `POST /api/vault/blind-check` (ohne Konto und Cookies, wie `/blind-sync`, 20 Anfragen je Minute). Er bestätigt `bucket_id` und Besitznachweis, legt aber nie einen Bucket an. Unbekannter Bucket und falscher Nachweis antworten gleich mit 401, damit die Antwort nichts über belegte Buckets verrät.
* `unlock` im Tresor-Store fragt diesen Endpunkt, wenn weder ein Canary noch ein Server-Bucket vorliegt. `/blind-sync` kam dafür nicht in Frage: für ein falsches Passwort hätte es per Trust-On-First-Use einen leeren Bucket registriert.
* Neue Meldung `mss.vault.errors.serverCheckFailed` (Deutsch und Englisch).
* Tests: Backend `test_vault_blind_check_bestaetigt_ohne_anzulegen`, Frontend „neues Gerät eines blinden Tresors“ in `vaultStore.test.ts`. Zusätzlich im Browser gegen ein eigenes Backend nachgestellt: Der alte Stand lehnte das richtige Passwort ab. Der neue lehnt das falsche ab, ohne einen Bucket anzulegen, und öffnet mit dem richtigen den Tresor samt Eintrag vom Erstgerät.
